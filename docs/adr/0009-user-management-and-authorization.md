# ADR-0009：用户管理、固定角色授权与管理员保底

- 日期：2026-11-09
- 状态：已采纳，已实现

## 背景

认证闭环和 admin/member 角色持久化已实现，需要通过 API 创建普通用户并管理账号状态与角色，为后续工作区归属隔离提供多用户基础。本决定落实 ADR-0005 的用户管理权限，并扩展 ADR-0008 的账号能力。

## 决定

### 业务与授权边界

账号管理放在 `internal/auth/users.go`，复用凭据验证、密码哈希、用户响应和现有数据库连接。HTTP 层通过独立的 `UserManager` 小接口调用业务；操作者 ID 从已认证的请求上下文取得，不接受请求体指定身份。

`internal/authz` 集中维护固定的角色权限映射，不增加策略库或动态权限表。每个用户仍有一个持久化角色；权限只覆盖当前已实现的管理动作：

| 权限 | admin | member |
| --- | --- | --- |
| `user:create` | 允许 | 拒绝 |
| `user:list` | 允许 | 拒绝 |
| `user:update_status` | 允许 | 拒绝 |
| `user:update_role` | 允许 | 拒绝 |

未知角色或动作默认拒绝。业务方法读取操作者的当前状态与角色，避免依赖 HTTP 层之前读取的权限快照。缺失或停用的操作者视为未认证；普通用户调用管理业务返回禁止访问。普通用户继续通过 `/api/v1/auth/me` 查询自己。

工作区权限与资源归属随工作区实现补充，管理员身份不隐含跨用户工作区或终端访问权。

### 用户操作

创建用户只接收用户名和密码，默认 active/member；角色调整通过独立接口进行。复用已有用户名唯一约束和 Argon2id 密码规则，创建用户及默认角色在同一事务内完成。

列表按 ID 升序进行游标分页，使用 `after_id` 和 `limit`；默认每页 50，最多 100，额外查询一条判断是否有下一页。返回显式公共用户结构和可选的 `next_after_id`，空列表为 `[]`。翻页不固定数据库快照，各页反映查询时的状态。

状态和角色分别通过 PATCH 接口修改，接受 application/json 的单字段对象。有效枚举为 active/disabled 和 admin/member。设置相同值返回当前用户，不修改 `updated_at`；发生变化时同步更新时间。停用账号复用数据库触发器撤销全部会话，重新启用不恢复旧会话。角色变化不撤销会话，后续请求读取新权限。

初始化、登录和创建用户共享原有进程内频率及并发限制，约束密码哈希工作量。JSON 请求继续限制为 16 KiB，拒绝未知字段；写操作复用全局 CSRF 保护，用户响应设置 no-store。

### 并发与最后管理员

用户管理 API 保留至少一个启用中的管理员。允许管理员修改自己的状态或角色，但若操作会移除最后一个 active/admin，则返回 409 `last_admin`；停用中的管理员不计入保底数量。

迁移 `00003_user_management.sql` 新增 `user_management_lock` 单例行。所有用户管理写事务使用 READ COMMITTED，先锁定该行，再检查操作者当前权限、读取目标并判断剩余管理员，最后提交修改。取得锁后的查询使用新快照，因此跨进程并发降级、停用和混合操作不会同时移除最后管理员，等待中的操作也不会继续使用已被撤销的管理权限。

列表在业务入口读取当前权限，不持有管理写锁；权限撤销不取消已经通过授权的列表读取。管理员保底约束由上述业务事务执行，维护 SQL 修改角色或状态时须遵循同一锁协议及保底检查。原有停用触发器仍覆盖直接 SQL 更新时的会话撤销。

## 备选方案

- 动态角色、权限表或通用策略库：当前仅有两种角色和四项管理动作，固定映射便于直接验证；出现自定义角色需求时再扩展。
- 分别锁定目标用户：两个管理员同时移除自己时锁定不同记录，仍可能同时通过数量检查。共同锁点能明确串行化这类变更。
- SERIALIZABLE 加事务重试：可以检测写偏差，但增加重试协议和失败语义；当前低频管理操作采用共同锁点更直接。
- 进程内互斥：无法协调多个服务进程，不作为数据库不变量的保证。

## 后果

管理写操作串行执行，创建用户的密码哈希也在事务内，吞吐适合当前低频管理场景。列表和认证不经过该管理锁。若管理写入量增长，再评估缩短持锁时间或调整锁粒度。

新增迁移回滚只删除管理锁表，保留用户、角色和会话；使用新接口前必须应用迁移。测试覆盖管理员与普通用户边界、游标分页、会话撤销、权限变更、并发保底、等待中的权限撤销以及更新失败后的事务回滚。

# ADR-0005：使用 RBAC 与资源归属约束管理资源访问

- 日期：2026-11-06
- 状态：已采纳；尚未实现

## 背景

用户要求以 RBAC 作为资源管理的授权基础。项目包含用户、模板、工作区与终端，同一种角色下的用户仍需要区分各自的资源。

## 决定

采用用户到角色、角色到权限的映射，以“资源类型 + 动作”描述权限，再用资源归属限定操作范围。Session 负责识别用户，RBAC 负责判断可执行的操作；额度、并发和任务执行由资源管理与调度模块负责。

初期角色沿用 `admin` 与 `member`。普通用户管理和连接自己的工作区；管理员在此基础上管理用户、角色、模板和资源额度。跨用户工作区操作与终端连接须单独明确授权范围，不从管理员身份隐含推导。

工作区权限区分创建、查看、启动、停止、删除、读取日志和连接终端。授权在业务入口统一执行，列表查询按授权范围过滤，异步操作入队前完成相应资源授权。任务执行期间权限变化的处理随任务模型明确。

角色关系由服务端持久化维护，使用当前权限做判断。具体权限矩阵和实现库在权限功能 PR 中确定；本决定不指定 Casbin 等库。实现原则参考 [OWASP 授权指南](https://cheatsheetseries.owasp.org/cheatsheets/Authorization_Cheat_Sheet.html)。

## 备选方案

只按角色判断无法表达同角色用户之间的工作区归属。直接逐用户授予全部操作权限可行，但重复维护较多；RBAC 用于管理常用权限集合，归属约束用于限定资源范围。

## 后果

HTTP、任务入口与终端访问使用一致的资源授权规则。权限变化需同步处理现有长连接。测试覆盖角色允许与拒绝、列表范围、跨用户操作和权限撤销。

# ADR-0011：SMTP 邮箱验证、主邮箱维护与先验证后注册

- 日期：2026-11-10
- 状态：已采纳，已实现

## 背景

[ADR-0010](0010-primary-email-and-password-change.md) 已提供数据库唯一主邮箱、验证状态和可选本地密码。下一步需要证明邮箱所有权，允许已有用户验证、补录或替换邮箱，并允许先验证邮箱再完成注册。项目可提供 SMTP，当前没有邮件队列或完整前端。

## 决定

### 临时证明与原子消费

新增 `email_actions`，每条记录包含 SHA-256 令牌哈希、用途、目标邮箱、可选 user_id、创建和过期时间。原始令牌使用 32 字节密码学随机数和无填充 base64url，只进入邮件与用户提交；有效期 30 分钟。用途区分 register、verify_email、change_email：注册不关联用户，维护必须关联用户。部分唯一索引限制每个邮箱只有一条注册申请、每个用户只有一条维护申请，重发替换旧证明。

注册申请不创建用户，也不占用 users 中的邮箱。持有有效证明后，用户提交用户名和密码；事务先锁定证明，再用独立语句按当前数据库时间删除仍有效的证明，创建 member、设置邮箱验证时间。先锁后检查避免在等待行锁期间过期的证明仍被消费。数据库唯一冲突或其他写入失败会恢复证明，过期前可重试。成功不自动登录。公开注册默认关闭，必须显式开启且实例已完成管理员初始化。

对已占用和未占用邮箱执行相同申请和发信流程，只有邮箱持有人完成证明后才看到账号邮箱冲突。这避免在公开申请接口泄露账号存在性，同时不把邮箱相同视作账号关联依据。

### 邮箱维护与并发

验证当前地址需要有效会话；补录或替换地址还需要确认本地当前密码。目标用户来自会话，不能由请求指定。验证新地址前保留旧邮箱及验证状态；确认后原子替换并标记已验证，数据库唯一约束决定并发冲突。确认需要同用户的当前有效会话，可以来自另一设备。

维护请求和确认、修改密码、登录沿用同一用户行锁，取得锁后重新检查会话归属、用户状态和实际过期时间。消费通过带用途、用户、`clock_timestamp()` 有效期条件的 DELETE RETURNING 完成，和账号写入在同一事务中提交。新增 `users_invalidate_email_actions` 触发器：主邮箱或密码改变、账号停用时，删除该用户所有待处理维护证明。邮箱确认不撤销会话；改密与停用继续沿用已有会话撤销规则。

成功换址后向旧邮箱发送安全通知；这是提交后的尽力投递，失败记录不含地址和正文的告警，不回滚主邮箱。无本地密码账号只能验证已有地址，不能通过密码式换址接口改变地址；OIDC 接入时另行提供对应的重新认证，继续使用本地 user_id 和未来 `(issuer, subject)` 绑定。

### 发信、限流与链接

通过小接口隔离业务和 SMTP。当前只有纯文本事务邮件，采用 Go 标准库 `net/smtp`，支持受验证的 STARTTLS 或 TLS 直连及 TLS 内 AUTH PLAIN，最低 TLS 1.2。标准库该包已冻结；本次不需要它未提供的模板、附件或现代认证扩展，后续出现需求时替换适配器。仅本地回环 IP 的测试服务可使用无认证明文模式。

发信连接、TLS、认证和提交共享 5 秒总期限，响应请求取消。SMTP 接受 DATA 即视为发送成功，后续 QUIT 失败不改变结果。没有持久化发件队列或自动重试；发送失败时删除该次证明，避免不确定投递后的链接继续有效。SMTP 连接不在数据库事务内。清理证明若遇到数据库故障返回内部错误；遗留证明仍受原有期限及一次消费约束。

新增 `email_delivery_limits`：规范化目标地址跨用途、跨进程共享一分钟冷却及小时窗口最多五次。配额和新证明在同一事务保留，发送失败、消费或重发不会重置配额。现有进程内 IP、全局及并发限流同时覆盖邮件端点。旧址变更通知不占证明邮件配额，仍受换址操作本身的限制。

邮件 URL 从可信配置生成，不依赖 Host 请求头；远程站点要求 HTTPS。令牌放入 URL fragment，避免进入 HTTP 访问日志和 Referrer。内嵌的注册、确认页面读取后清除片段，不使用第三方脚本或本地持久化，设置 no-store、no-referrer 和 CSP。GET / HEAD 只展示界面，用户明确提交后才 POST 消费，避免预览链接产生变更。密码找回留待独立流程实现。

### 迁移与清理

迁移 00005 新增证明、配额表及失效触发器，保留已有用户、邮箱、密码、角色和会话；未验证邮箱和旧账号的空邮箱均可继续登录。每小时清理过期证明和结束冷却的过期配额，验证和限流不依赖后台清理。

回滚 00005 删除待处理证明与配额及触发器，保留已完成的注册、邮箱变更和验证状态。重新升级后必须重新申请证明。若继续回滚 00004，沿用其邮箱删除与无密码账号限制。

## 备选方案

- 先建立未激活用户：会提前占用邮箱和用户名，并将临时申请混入正式用户生命周期。当前使用单独证明表，只有消费成功才建号。
- 把邮件令牌编码为自包含 JWT：一次消费、撤销和重发仍需要服务器状态。随机令牌加哈希存储更直接。
- 通过 GET 完成验证：邮件扫描器、预取和转发可能提前消费。选择显式 POST，增加最小确认页面。
- 引入邮件队列和通用模板库：当前流量和邮件类型有限，先采用有超时的同步 SMTP；可靠重试、退信跟踪与模板按需求再设计。

## 后果

外部 SMTP 足以完成当前学习项目的证明流程，部署需配置允许的发件地址、TLS、凭据及站点 URL，并验证实际入箱情况。接口成功只说明 SMTP 接受，不保证最终送达。新功能保持默认关闭，不改变已有账号的登录方式。

测试使用本地 SMTP 服务验证 TLS、认证、证书拒绝、发送失败和取消，用真实 PostgreSQL 验证唯一性、重放、并发配额、会话失效、原子回滚和迁移，并覆盖真实 HTTP Cookie 的注册与换址闭环。

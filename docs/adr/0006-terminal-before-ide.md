# ADR-0006：先实现 xterm.js 终端，后续集成浏览器 IDE

- 日期：2026-11-06
- 状态：已采纳；尚未实现

## 背景

资源调度完成后，需要让用户实际使用工作区。用户确定先实现 xterm.js 终端，再完成 VS Code 等 IDE 集成。

## 决定

第一阶段在 Vue 中提供 xterm.js 终端，通过 WebSocket 与 Go 服务通信，接入工作区内的交互式 shell。当前 Docker 方向优先使用 exec TTY；连接库与消息协议在实现时确定，候选见 [工作区访问设计](../workspace-access.md)。

终端入口复用 Session 与 RBAC，并验证工作区归属。首阶段验收覆盖交互输入输出、Ctrl+C、窗口缩放、断连处理、资源清理和访问隔离。

终端闭环完成后，再集成浏览器 IDE、语言服务及开发服务入口。code-server 是优先评估的候选，具体产品与代理方案届时决定。

## 备选方案

先集成完整 IDE 可以复用其终端，但会提前引入应用代理、编辑器配置与扩展环境。独立终端可以先验证资源访问闭环，同时学习 Go 的实时通信。

## 后果

第一阶段不依赖完整 IDE。后续 IDE 可能自带终端，独立终端继续作为轻量入口；两者共享工作区、会话和授权规则。

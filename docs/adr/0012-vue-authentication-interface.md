# ADR-0012：Vue 认证界面与同源部署

- 日期：2026-11-17
- 状态：已采纳，已实现

## 背景

认证、注册与邮箱维护 API 已完成。内嵌的最小注册和确认页面缺少登录入口，用户需要通过命令行建立浏览器外的会话，无法在页面中完成连续操作。项目希望学习 Vue，并继续以一个 Go 服务交付。

## 决定

采用 Vue 3、TypeScript、Vite 和 Vue Router，在仓库 `web/` 建立前端工程。使用官方 create-vue 初始化，依赖固定精确版本并保留 npm 锁文件；Node LTS 由根目录 `.nvmrc` 固定。版本与来源见 [前端开发](../frontend.md)。

首批页面覆盖管理员初始化、邮箱注册、登录、邮箱确认和账号资料。账号页面提供邮箱验证、补录、换址与退出。页面调用现有 API，密码、权限、会话和令牌消费规则继续由 Go 执行。前端只在内存保存用户展示状态，通过 `/auth/me` 恢复会话；不在浏览器存储中保存密码或会话令牌。

开发时 Vite 监听 `127.0.0.1:5173`，将 `/api` 和 `/healthz` 代理到 Go 的 `127.0.0.1:8080`。请求保留浏览器原始 Host，不开放 CORS 或关闭 Go 的同源保护。邮件 Public URL 指向浏览器实际访问的 origin。

生产构建将 `web/dist` 嵌入 Go 二进制。Chi 仅对明确的页面路径返回 SPA 入口；未知 API、资源和路径继续返回 404。Vue Router 使用 history 模式，页面刷新可由 Go 直接提供入口。Vite 生成带内容哈希的资源可长期缓存；HTML 禁止缓存并设置 CSP、no-referrer 和防嵌入策略。

注册与确认链接保留现有路径和 `#token=` 格式。应用在创建路由器前读取并移除片段；停留在同一页面打开邮件链接时，路由守卫也读取并清除片段。令牌只在对应页面内存中存在，GET 不消费证明。邮箱确认页在未登录时原地显示登录表单，登录成功后仍需显式点击确认。刷新或离开页面后，需要从原邮件重新打开链接。

Go 构建需要先构建前端；Makefile 为相关目标提供该依赖，发布脚本也构建前端。源码不提交 node_modules 或 dist，发布包中的服务二进制包含完整 UI，无需运行 Node。

## 验证

Vitest 检查 API 错误、会话状态、令牌处理和重发冷却。Go 测试检查页面与 API 的路由边界、安全头和资源缓存。独立的 `make test-browser` 在真实 PostgreSQL 随机 schema 上启动应用，通过 Playwright 检查初始化、注册、Cookie、刷新、邮箱验证、换址与退出，以及 Vite 代理下的同源校验；收件箱仅存在于测试服务，生产路由没有读取邮件的接口。

## 备选方案

- 继续维护静态 HTML 表单：初期依赖较少，但多个账号页面开始重复处理会话与交互，不能落实 Vue 学习目标。
- 单独部署前端域名：引入跨源 Cookie、CORS 与 CSRF 配置；当前同源方案足够。
- 将前端资源作为独立目录发布：避免嵌入构建依赖，但部署时需要维护额外文件。当前选择单二进制携带资源。

## 后果

前端构建与测试增加 Node 工具链；直接使用 `go run` 或 `go test` 前需执行 `make web-build`。后续工作区页面可以复用工程与会话边界。新增前端页面时，需要同步 Vue Router 与 Go 的页面路径清单。SMTP 出站连接仍由 Go 负责，Vite 的 HTTP 代理不改变 SMTP 网络路径。

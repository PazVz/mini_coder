# ADR-0010：主邮箱、可选本地密码与密码修改

- 日期：2026-11-09
- 状态：已采纳；邮箱基础与修改密码已实现，邮件验证、自助注册和 OIDC 待实现

## 背景

账号目前通过用户名和密码登录，需要增加用户主邮箱与密码修改，并为先验证邮箱再注册、邮件找回和第三方登录保留兼容。此次交付邮箱数据基础与修改密码；SMTP 和主邮箱的自助补录、修改在下一次迭代一起提供。

本决定扩展 ADR-0007 的用户模型、ADR-0008 的认证与会话规则，以及 ADR-0009 的管理员创建用户输入。

## 决定

### 主邮箱与唯一性

每个用户维护一个主邮箱，本地 `users.id` 继续作为身份、角色和资源关联的稳定键。邮箱不作为用户主键，也不作为未来外部身份的关联键。

`users` 增加以下字段：

| 字段 | 作用 |
| --- | --- |
| `email` | 去除首尾空白后的原地址，保留大小写，用于展示和未来投递 |
| `email_key` | PostgreSQL 生成列 `lower(email COLLATE "C")`，通过 `users_email_key` 唯一约束保证跨用户、跨进程唯一 |
| `email_verified_at` | 邮箱验证完成时间；NULL 表示未验证，与账号 active/disabled 独立 |

本项目将整个邮箱按 ASCII 大小写不敏感比较。这是产品规则，SMTP 中本地部分理论上可以区分大小写。保留点和 `+` 后缀，不做提供方特有的地址合并。

第一期支持单个 ASCII 地址，本地部分使用 dot-atom，域名使用 DNS 名称。Go `net/mail` 解析后拒绝显示名、注释、引号本地部分、地址列表、IP 字面量和 SMTPUTF8 地址；本地部分最多 64 字节，域名标签最多 63 字节，整体最多 254 字节。数据库约束保证非空地址为无空白的 ASCII 邮箱形式及长度上限，完整语法由业务边界校验。

首次管理员初始化和管理员创建用户均要求邮箱、用户名和密码。数据库唯一冲突映射为 409 `email_taken`；与创建用户、分配角色或完成初始化相关的写入整体回滚。公共用户增加 `email`、`email_verified`；不暴露比较键或数据库类型。

升级时保留已有账号的邮箱为 NULL，不生成占位地址，也不把地址视为已验证。公共响应以空字符串和 false 表示待补录；其已有密码登录、会话、状态和角色继续有效。新建账号的邮箱也保持未验证，现阶段仅用于保存资料，不能用于找回密码或关联外部身份。初始化和管理员创建仍是受控的账号配置入口；公开自助注册尚未开放。

本次不提供邮箱自助写接口。下一次迭代通过验证流程补录或替换主邮箱；替换前保留旧邮箱，确认新邮箱后再原子更新。已有邮箱完成补录后，再评估收紧数据库非空约束。

### 可选本地密码

`password_hash` 允许 NULL，表示账号没有本地密码；非 NULL 值仍须非空，密码认证仍采用当前 Argon2id 参数。密码登录对无密码账号执行虚拟哈希校验后返回统一的 `invalid_credentials`，不将缺失密码作为内部错误。

本次两个账号创建 API 仍要求密码。数据库兼容无密码账号，不增加 OIDC 配置、回调或外部身份表。未来增加 `(issuer, subject)` 唯一的外部身份记录并关联 `user_id`；邮箱相同不自动合并账号，绑定要求认证已有本地账号并验证待绑定身份。无本地密码账号新增密码须有独立的重新认证流程，不能借用修改密码接口。

### 修改密码与会话撤销

`POST /api/v1/auth/password` 接收 `current_password`、`new_password`，目标用户只能来自认证上下文。HTTP 层执行现有 CSRF、JSON 边界和密码计算共享限流。

业务事务锁定用户行，再根据当前 Cookie 的令牌哈希重新检查会话归属、过期和账号状态。过期判断使用 `clock_timestamp()`，防止等待锁后仍采用事务开始时间。没有本地密码返回 409 `password_not_set`；当前密码错误返回 403 `invalid_current_password`。新密码沿用至少 12 个 Unicode 字符、最多 1024 字节的规则。

验证当前密码后生成新哈希并更新时间。迁移 `00004_email_and_password.sql` 扩展 `users_revoke_sessions`：账号停用或 `password_hash IS DISTINCT FROM` 旧值时，撤销全部会话，包括当前会话。密码修改和会话删除在同一事务中提交，任一步失败均回滚；设置或移除本地密码也触发撤销。

登录和修改密码共享用户行锁。旧密码登录若先提交，其会话会被随后改密撤销；若在改密后取得锁，登录会比较当前密码哈希并拒绝旧凭据。排队的改密请求在拿锁后重新检查会话，不能继续使用已被撤销的 Cookie。

成功响应为 204，并清除浏览器 Cookie，用户使用新密码重新登录。改密不改变账号角色、邮箱或验证状态。密码哈希计算期间持有用户锁，适用于当前低频单体场景。

### 后续邮件流程的令牌边界

以下是已确定的后续设计，本次没有实现邮件令牌表、发信或消费接口：

- 自助注册先验证邮箱，再设置用户名、密码并创建 member；临时验证申请过期清理，不长期占用正式用户邮箱。
- 邮箱验证、密码找回、邮箱替换使用独立用途的令牌；每个令牌由密码学安全随机源产生至少 32 字节随机数，只保存 SHA-256 哈希，并绑定用途、目标邮箱或用户、有效期和消费状态。
- 消费令牌与创建账号或变更凭据在同一事务内完成；过期、重放、用途或目标不符均拒绝。完成重置后撤销其他重置令牌和全部会话。
- 邮件链接使用受信任配置的站点 URL；GET 仅展示确认界面，POST 执行变更；日志不记录原始令牌或完整验证链接。申请与重发按 IP 和邮箱限流，找回请求使用统一响应。
- 未来 Google 登录使用 OIDC 验证后的 `(issuer, subject)` 建立身份关系，继续签发本地 Session Cookie。

## 备选方案

- 升级时直接把邮箱设为 NOT NULL：已有账号没有真实邮箱，无法安全回填。采用可空迁移并对新建 API 强制要求，等待验证流程完成补录。
- 仅在应用中查询邮箱是否存在：并发写入仍会竞争。由数据库生成统一比较键并执行唯一约束，应用负责映射错误。
- 为无密码账号存放随机密码哈希：无法直接区分认证方式。NULL 明确表示没有本地密码。
- 改密后仅撤销其他会话：需要额外处理当前会话轮换。本次统一撤销全部会话并重新登录，便于验证并发与失败行为。

## 后果

初始化和管理员创建用户增加必填 `email`，属于请求契约变更；用户名登录请求不变。旧账号继续可用，待邮件验证上线后补录邮箱；本次不把邮箱未验证解释为账号停用。

第四版迁移回滚会删除邮箱信息、恢复密码非空要求及仅停用撤销会话的触发器。如果存在 NULL 密码，回滚原子失败，保留数据和当前结构；必须先明确处理这些账号的登录方式，不能自动填充密码。

测试覆盖邮箱输入、数据库唯一约束与并发冲突、旧账号升级和回滚、无密码账号、修改密码权限与 Cookie、全部会话撤销、并发等待后的凭据和会话检查，以及撤销失败时的事务回滚。

# 项目目标与路线

## 学习目标

以 [Coder](https://github.com/coder/coder) 为参考，独立实现一个可在本地运行的开发工作区管理平台。通过实际功能学习 Go 的 HTTP API、认证授权、持久化、并发任务和资源管理；通过持续迭代学习 Vue 前端、测试、Conventional Commits、CI/CD 与 semantic-release。

## 核心闭环

用户登录后，从模板创建自己的工作区，查看启动进度并使用开发环境，随后停止或删除资源。管理员管理用户、角色和资源额度。

| 能力 | 初期目标 |
| --- | --- |
| 用户与权限 | Session + Cookie 登录会话、RBAC 角色权限、工作区归属和访问控制 |
| 模板与工作区 | 定义镜像和资源参数；创建、启动、停止、删除工作区，保存状态 |
| 资源执行与调度 | 通过 Docker Engine 执行任务，控制并发与额度，记录结果；逐步加入定时停止和失败恢复 |
| 访问与可观测性 | 展示操作日志和状态，先实现 xterm.js 实时终端，后续集成浏览器 IDE 与开发服务访问 |
| Web 界面 | 优先 Vue，实现登录、工作区列表与详情、生命周期操作和管理页面 |
| 开发与交付 | 每个 PR 可本地验证；逐步建立自动检查、版本管理和发布流程 |

第一阶段的调度面向单个 Docker 环境中的任务执行、资源额度与生命周期。多主机放置、Kubernetes、多云、Terraform 扩展和高可用在核心闭环完成后按学习需要推进。

## 当前基础

已具备 Go 服务、`/healthz`、优雅退出、PostgreSQL 连接、Goose 迁移、sqlc 用户创建与查询、单元与数据库集成测试、Makefile、PR 标题检查、CI 和标签发布脚本。开发与交付方式见 [协作与发布](workflow.md)。

用户 API、认证授权、工作区业务和前端尚未实现。下一步实现首次管理员初始化、密码认证与 Session + Cookie 登录闭环，再增加用户管理及 RBAC。

## 建议推进顺序

以下是阶段目标，每个阶段可拆成多个可独立评审的 PR，按实际学习反馈调整。

| 阶段 | 交付内容 | 验收方向 |
| --- | --- | --- |
| 0：文档基础 | 文档入口、AI 约定、ADR、当前协作流程 | 能区分已实现能力与后续计划，并按文档启动和验证项目 |
| 1：身份与数据 | 数据库与迁移、用户、Session + Cookie、RBAC | 数据可持久化；登录、退出与会话过期可验证；角色权限及资源归属有效 |
| 2：工作区闭环 | 最小模板、工作区 API、Docker 生命周期 | 创建、启动、停止和删除可验证；所有者隔离有效；状态与容器一致 |
| 3：任务与资源 | 异步任务、并发控制、额度、定时停止与操作日志 | 长任务有可查询结果；重复请求与失败恢复有明确行为；资源限制生效 |
| 4：前端与实时终端 | Vue 界面、xterm.js、WebSocket 与工作区 shell | 用户能操作工作区并交互执行命令；终端权限、缩放、断连清理和数据持久化可验证 |
| 5：IDE 集成 | VS Code 类浏览器 IDE 与开发服务入口 | 文件编辑、保存、语言服务、编译运行与工作区访问隔离可验证 |
| 6：交付演进 | semantic-release、版本说明、发布与部署练习 | 提交历史可解释版本变化，构建产物可验证，发布过程可重复 |

测试和 Conventional Commits 从当前阶段持续实践。Vue 可在 API 首个闭环形成后同步学习；发布自动化与 semantic-release 可随功能迭代推进，持续保留本地验证入口。
